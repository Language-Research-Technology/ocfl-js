# The API report is the public API contract

## Context

Everything public is a commitment. The published types should change only on purpose, and every change to them should be visible in review.

## Decision

- **The entry point exports an explicit list.** `src/index.ts` names every export: the functions `createStorageRoot()` and `openStorageRoot()`, the class `OcflError`, and types. It has no default export and no `export *`. Everything else is reached through those two functions.
- **The objects a storage root gives are published as interfaces.** `StorageRoot`, `OcflObject`, `Version`, `OcflFile`, `Draft` and `UnfinishedWrite` are interfaces, and the classes behind them aren't exported.
- **`OcflError` is the only published class, and only the library makes one.** It is a class so callers can use `instanceof`. It has no subclasses: callers test `code`. Its constructor is private, and the factory the library uses is tagged `@internal`, which `stripInternal` removes from the published types.
- **The API report is the contract.** `etc/ocfl-fs.api.md`, generated by api-extractor, lists the public API. `pnpm lint:api` runs in CI and fails when the built API differs from the report, when a public member has no doc comment, or when api-extractor warns, for example about a public signature that uses a type the entry point doesn't export.
- **Every export states its type.** The build sets `isolatedDeclarations`, so an export whose type can't be read off its declaration fails to compile.

## Consequences

- Every change to the public API shows up in its pull request as a diff to the API report. A diff that removes or changes something already in the report is a breaking change.
- Exporting a class behind one of the interfaces as a value contradicts this decision and needs a new ADR first.
- Editing a function body can't silently change a published signature.
